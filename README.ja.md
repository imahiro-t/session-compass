# Session Compass

[English](README.md) | 日本語

Claude Code のプロンプトの上に帯を出すプラグインです。帯の左側には、このセッションで何をしているかが出ます。これまでの依頼をまとめた 1 行の要約です。右側には、会話の中の自分のプロンプトを行き来するボタンが並びます（⏫ 最初へ、🔼 前へ、🔽 次へ、⏬ 最新へ）。要約はセッションの進み方に合わせて作り直され（プロンプトのたびに、または 🔁 を押したときだけ。設定で選べます）、Claude からの質問ダイアログの上にも出ます。

## 動き

### 要約

- プロンプトを送るたびに、最初のプロンプトと直近のプロンプト（最大 8 件）から要約を作り直します。その間の依頼の流れは、前回の要約を添えて引き継ぎます。話題が移れば要約もそれに合わせて変わります。要約はモデル（haiku）の呼び出しで作ります。
- 新しい要約を作っている間や、作るのに失敗したときは、前の要約を表示したままにします。
- スラッシュコマンドは、引数があるとき（`/graph-ops:process-ticket SCMP-00001` など）は依頼に数えます。引数の無いもの（`/clear`、`/config` など）は数えません。
- `manual` モード（[`summaryMode`](#summarymode) を参照）でも、最初の要約は自動で作ります。それ以降は、帯の 🔁 を押したときだけ作り直します。
- 要約はテーマの `claude` 色の太字で表示します。ライト／ダークどちらのテーマでも、通常の文字と見分けやすくしています。

### ボタン

- 🔼 と 🔽 は 1 つ前・1 つ後のプロンプトへ移動します。移動先は自分のプロンプトだけで（スラッシュコマンドも含みます）、通知や他のエージェントからのメッセージなどは含みません。移動すると、そのプロンプトの行が会話欄の一番上に来ます。
- ⏫ はセッションの一番最初のプロンプトへ、⏬ は会話の一番下（最後のターンを締める所要時間の行、または最新の行）へ移動します。どちらもセッションの記録ファイルを読んで移動先を決めるので、長いセッションや再開したセッションでも、まだ画面に描画されたことのない遠くの行まで届きます。
- 会話欄を自分でスクロールしたあとは、いま読んでいる位置から数えます。🔼 は画面に出ている返答のプロンプトの先頭へ戻り、🔽 は次のプロンプトへ進みます。スクロールしていなければ、最後にボタンで移動した位置から数えます。
- ボタンで移動した先のプロンプト行には背景色が付きます（テーマの `diffAddedDimmed` 色。行の左端には `claude` 色の `▌` の印も付くので、色が区別できなくても位置がわかります）。どこへ移動したかがひと目でわかります。別のプロンプトへ移動すると背景色もそちらへ移り、新しいプロンプトを送ると消えます。⏬ で会話の一番下へ移動したときは、最新のプロンプト行に背景色が付きます。ただし、そのときその行が画面に見えているとは限りません（最新の返答が長ければ、画面の上の外にあります）。

### 質問ダイアログ（AskUserQuestion）の表示中

質問ダイアログが出ている間はプロンプトの場所がダイアログになり、帯も隠れます。そのときは、要約をダイアログの上に 1 行で表示します。切る幅は帯と同じなので、同じウィンドウ幅なら帯と同じ文字数まで表示されます。ボタンは表示しません。ダイアログには帯のような本文幅の値が無いため、ウィンドウの列数から帯の本文幅を計算しています。会話欄の横にペインを出しているときは、帯と数セルずれることがあります。

### Claude の出力の折りたたみ

- Claude の出力のブロックのうち、2 行以上になるもの（折り返しも数えます。改行のない長い 1 段落も対象です）には、左端に開閉マーカーが付きます。開いているときは `▼`、折りたたんでいるときは `▶` です。1 行で収まるブロックには付きません（本文の前後の空行は数えません）。
- 初期状態はどのブロックも展開です。マーカーをクリックすると折りたたみ、もう一度クリックすると開きます。マーカーはテーマの `claude` 色の太字で描きます。コントロールを読み上げる画面では、押したときの動作が名前になります（「Fold output」/「Expand output」）。出力の本文は Claude Code 自身の色と描画のままで、文字色は変えません。
- 折りたたんだブロックは 1 行だけを表示します。先頭の本文の行を、markdown の装飾を外して画面の幅で切ったもので、その行のほかにも本文があれば `…` が付きます。コードブロックや表で始まるブロックでは、コードや表の区切り線ではなく、最初の本文の行（表ならヘッダのセル）が出ます。コードだけのブロックでは、コードの最初の行が出ます。
- 折りたためるのは Claude の返答の本文のブロックだけです。ツールの呼び出しとその結果の行は対象外です（そちらは Claude Code 自身が ctrl+o で折りたたみます）。

### 送信されるもの

- 要約のために、最初のプロンプトと直近のプロンプト（各 600 文字まで）を、前回の要約（200 文字まで）と一緒に haiku に送ります。`auto` ではプロンプトのたび、`manual` では 🔁 を押したときです。
- ⏫ と ⏬ は、手元のマシンの `~/.claude/projects/` の下にあるセッションの記録ファイルを読みます（`head` と `tail` で、先頭 2 MB か末尾 200 行）。どこにも送信しません。

## インストール

このリポジトリはそれ自体がマーケットプレイスです（`.claude-plugin/marketplace.json`、名前は `session-compass`）。Claude Code のターミナルセッションのプロンプトで、次を実行します。

```
/plugin marketplace add imahiro-t/session-compass
/plugin install session-compass@session-compass
```

1. プラグインの詳細が表示されたら、スコープを選びます（ユーザースコープなら以降のすべてのセッションで有効になります）
2. 設定画面で `summaryMode` を選びます（初期値は `auto`）
3. `Installed session-compass. Plugin is now active.` と表示されたら、そのセッションですぐに使えます

Session Compass は [erin-the-black-plugins](https://github.com/imahiro-t/claude-plugins) マーケットプレイスにも登録されています（そちらからインストールした場合、下の設定例のキーは `session-compass@session-compass` ではなく `session-compass@erin-the-black-plugins` になります）。インストールはどちらか一方のマーケットプレイスからだけにしてください。両方から入れるとフックが二重に登録され、帯が 2 つのプラグインから描かれます。乗り換えるときは、先に入っている方をアンインストールしてください。

## 設定（userConfig）

### `summaryMode`

帯の要約をどう作り直すか。`auto`（初期値）か `manual` です。

| 値 | 動き |
| --- | --- |
| `auto` | プロンプトを送るたびに要約を作り直します |
| `manual` | 最初のプロンプトの要約は自動で作ります。それ以降は、帯の 🔁 を押したときだけ作り直します。新しいプロンプトが無くても、🔁 を押せば作り直します |

`/config` から変えるか、設定ファイルに書きます。

```json
{
  "pluginConfigs": {
    "session-compass@session-compass": {
      "options": { "summaryMode": "manual" }
    }
  }
}
```

## 既知の制限

- 折りたたみとハイライトが効くのはフルスクリーン表示のとき（と、会話の行を描き直すリモートの画面）です。メイン画面（非フルスクリーン）では、ターミナルのスクロールバックに書き出された行は描き直されないので、折りたたみもハイライトも反映されません。ボタンでの移動も、もともとフルスクリーンが前提です。
- 開閉マーカーはクリック（マウス）でしか押せません。会話欄の中のボタンはキーボードのフォーカスを取れないため、キー操作はありません。
- 2 行以上かどうかは装飾を外した文字の幅で数えます。そのため、markdown の装飾（見出しの記号、リンクの URL など）で描かれる幅が変わると、ちょうど 1 行のブロックにマーカーが付くことがあります。その場合も、折りたたむと同じ 1 行が出るだけです。
- 折りたたみの状態は、ブロックのメッセージ ID ごとに持ちます。出力中に仮の ID で描かれたブロックは、本来の ID が付いたあとで開いた状態に戻ることがあります。
- 会話欄の上部に出る Claude Code 自身の表示（スクロール中に、いま読んでいるプロンプトを示すもの）が、🔽 で移動した先の 1 つ前のプロンプトを示すことがあります。この表示は Claude Code のもので、このプラグインは手を加えません。

## 開発

開発中は、このフォルダからデバッグログ付きで読み込んで動かします。

```sh
claude --debug --plugin-dir .
```

ファイルを保存すると、そのセッションでプラグインが読み込み直されます。変更を入れる前に、次で確認します。

```sh
claude plugin validate .
claude plugin test .
```

## リリース手順

1. `.claude-plugin/plugin.json` の `version` を上げ、その変更を `main` にマージする
2. その `main` のコミットに `vX.Y.Z` のタグを付けて push する: `git tag vX.Y.Z && git push origin vX.Y.Z`
3. [imahiro-t/claude-plugins](https://github.com/imahiro-t/claude-plugins) の `.claude-plugin/marketplace.json` で、`session-compass` のエントリの `ref` を新しいタグにする
4. claude-plugins のルートで `claude plugin validate .` を実行し、通ったらその変更を claude-plugins の `main` に入れる
5. （任意）一時的な設定ディレクトリで、erin-the-black-plugins からのインストールを試す。どのコマンドにも同じディレクトリを使う:

   ```sh
   TMP=$(mktemp -d)
   CLAUDE_CONFIG_DIR="$TMP" claude plugin marketplace add imahiro-t/claude-plugins
   CLAUDE_CONFIG_DIR="$TMP" claude plugin install session-compass@erin-the-black-plugins
   rm -rf "$TMP"
   ```

タグは、`ref` の変更が claude-plugins の `main` に入る前に push してください。タグが無い間は erin-the-black-plugins からのインストールが失敗し、`claude plugin validate .` はそれを検出しません。
